# 站点侧依赖：这份主题单独装是跑不起来的

> 这份文档和站点侧样例在 2026-10-06 第 P 轮曾被整块搬到主题外面（同级 `mustom-extract/`），同日第 R 轮按"仓库要只剩这个主题"又搬回主题，落在 `docs/`：本文件和《对比原版》在 `docs/`，样例在 `docs/example-site/`。`docs/` 不是 hexo 认识的目录（主题的 `source/`、`layout/`、`_config.yml`、`scripts/` 四样之外它一概不读），所以这一层完全不影响构建，产物里也搜不到它（实测 `_tmp/roundN_build_verify.txt` 第 4 节）。主题 `README.md` 把第一节那张"要放到站点哪里"的表内联了一份，所以只拿主题目录也能装；本文件留着完整口径和构建自检记录。文中 `_tmp/...` 指的是本仓库之外的工作脚本目录，那批探针与对拍脚本不随主题分发。

TL;DR：主题的 `layout/`、`source/`、`scripts/`、`_config.yml` 是完整的，但它有 6 处伸手要站点根目录下的东西——歌单数据、`/live/` 那一页、RSS、正文序号与摘要所需的两条站点配置、构建期注入正文的两个工具脚本、以及 CI 里多出来的两步。这些原样拷在 `example-site/site/` 里（就在本文件旁边），装到别的站点时按下面的对应位置放回去即可。`docs/` 不是 hexo 认识的目录，hexo 构建时不会读它，也不会进产物。看板娘的运行时以前也在这一层，2026-10-06 第 Q 轮移回主题了，同日第 R 轮又把其中与上游发布件逐字节相同的 3 件改成外链（见第一节课后的说明和《对比原版》第十节）。

这份模板已经脱敏（个人标识换成占位、无引用的文件删掉、看板娘模型不打包），逐项替换记录在《对比原版》第九节。凡是这一份里写成 `your-…`、`My Blog`、示例数据的地方，都是等你填的位置；原值在 `blog` 仓库的同一个键上，本模板不含。

## 一、`example-site/` 里有什么、放到哪

下表"这里的文件"都相对 `docs/example-site/site/`，也就是把 `site/` 那个目录整个盖到站点根上。

## 二、CI 里多出来的两步

`example-site/site/.github/workflows/deploy.yml` 就是仓库里那份 workflow 的快照，它在 `npx hexo generate` 与部署之间插了两步：

```
- run: npx hexo generate
- run: node tools/search_index.mjs public      # 正文注回 HTML
- run: npx pagefind --site public              # 产出 public/pagefind/
```

少了第三步的话，弹窗搜索（`source/asset/js/part/search.js`）取不到索引；少了第二步的话，索引里搜不到正文内容。

## 七、本地构建与验收

```
deno run -A npm:hexo clean && deno run -A npm:hexo generate
```

两条硬规则：`.styl` 和页内脚本改完必须 `clean` 再 `generate`，增量构建会静默不重编（实测过一次增量只重写 17 个文件、`public/asset/css/style.css` 时间戳都没动）；别在站点目录跑 `deno install`（会裁坏依赖）。本机没有 node，运行时是 Deno。

验收：线上只用 `curl`（浏览会给不蒜子计数）；要看版面就在本地 `python -m http.server 4171 --directory public` 上跑 headless Firefox 探针（`_tools/ffshot.mjs`、`_tmp/round*.mjs` 那一套）。`/asset/part/*.html` 在线上取回 0 字节是正常现象。

## 八、这份模板自己能不能跑：10-06 实测

在一个空站点里把主题装进去构建了一遍（`_tmp/tpl_site/`），结论是能跑，但有一个坑必须先说。`_tmp/tpl_site/themes/mustom/` 是 10-06 04:37 那一刻的**拷贝**，不是链接；模板后来又改过的话这里就是旧的，重跑前先 `rm -r` 再拷一遍，别拿它的产物当模板现状。

**主题目录不能用 junction/symlink 挂进 `themes/`。** 实测用 `mklink /J` 把 `themes/mustom` 指向模板目录时，hexo 不加载主题自己的 `scripts/`，表现是：`/asset/part/*.html` 32 个全 0 字节、`browser.html` 0 字节、产物里没有 `/api/` 整个目录、渲染 `layout/_partial/_part/footer.ejs` 抛 `version is not defined`（那个变量本来由 `scripts/renderer/$partplus.js` 注入），而 `hexo generate` 照样退 0、照样报"130 files generated"。换成**整目录拷贝**进 `themes/mustom/` 之后 0 error 0 warning（只有 deno 的一条 punycode DeprecationWarning），133 个文件、1,324,976 字节（第 R 轮之前是 151 个、4,436,216 字节；少的 18 个就是出库改外链的 15 个字体文件加 3 件看板娘运行时）。所以别人装的时候要么真拷目录，要么用 git submodule，别图省事挂链接。

装法就是第一节那张表：站点 `_config.yml` 直接抄 `docs/example-site/site/_config.yml`，`scaffolds/`、`source/data/bili-playlist.json`、`source/live/index.md` 放回对应位置（看板娘运行时已经在主题里，站点不用再放），再写两篇 post 和一个 `parts: [page]` 的页面。

产物验收跑三个脚本（`_tmp/roundN_build_verify.py`、`_tmp/roundN_dangling.py`、`_tmp/roundN_dead_sweep.py`，输出同名 `.txt`；2026-10-06 第 R 轮那次是整目录拷贝后 `clean` + `generate`，133 个产物文件）：
